# 星际茶餐厅

English name: **Interstellar Cha Chaan Teng**

RimWorld 1.7 模组。生产食品级聚丙烯塑料颗粒和片材，将加工食品封装为包装生存食品，并提供塑料互转、工程塑料零部件配方。依赖 Harmony。

## 可包装食品的确定规则

每次游戏定义加载完成后，DLL 从所有已加载的 `ThingDef` 重建三种包装配方的原料范围，不按模组名称维护白名单。切换语言和开发者定义重载也会重建。

普通食品须同时满足：

1. 是可食用物品，食物类型允许人类食用。
2. 游戏解析、继承及补丁处理后的营养值为有限正数。不设最低营养门槛。
3. 不是尸体、生食原料类别 `FoodRaw` 及其子类，也不是药物或 `Drugs` 类别。
4. 食物类型包含 `Meal` 或 `Processed`，或归入 `FoodMeals` 类别及其子类。

因此餐食、干肉饼、婴儿食物、巧克力、日光果果汁及符合规则的模组加工食品都会自动纳入。`NeverForNutrition` 只影响自动进食偏好，不会阻止包装。仅仅“有生产配方”不视为加工食品，例如人造生肉仍然排除。食品自己的营养数值照单全收，不根据市场价格、心情、餐食品级或来源配方重新平衡。

包装生存食品 `MealSurvivalPack` 默认不可再次包装，可通过默认关闭的彩蛋选项开放，仍只按其实际营养值计量。三种配方保持原有投入与产出：

| 产出包装生存食品 | 塑料片 | 食品营养值 |
|---|---:|---:|
| 5 份 | 5 | 4.5 |
| 9 份 | 9 | 8 |
| 13 份 | 12 | 12 |

**营养计量上，包进去众生平等。** 简单、精致、奢侈只按实际营养值计量，可混用；塑料仍按个数计量。默认不继承熟食的直接食用心情，是否保留由独立的实验设置决定，不影响计量。不可拆分的食品按原版取整取料，因此一批只用 C 口粮时分别需要 3、4、6 份，多余营养不退回。原有损耗、成本、产量、工时及其他配方数值均未改动。

## 包材与食材记录

塑料片是固定耗材，不出现在订单右侧的可选食品菜单，不用勾选，仍须备足并消耗原定的 5 / 9 / 12 片。订单的需求说明仍显示包材用量；已有订单也不需要重建或修改塑料勾选。

新制作的包装生存食品仅记录食品，不把食品级塑料片列作食材。例如只使用 C 口粮时，显示「原料：C口粮」。包材处理仅为 `MealSurvivalPack` 添加一个无状态组件，不替换原版食材组件；这项处理不需要 Harmony。其他食品的包材记录行为不变。

不扫描存量、不在读档时清理：旧成品原有记录保持不变。若按原版规则允许堆叠，合并双方会在原版食材合并前排除塑料，避免重新污染新堆，也避免塑料占用三种食材的记录上限。部分合并的剩余旧堆也会在此次操作中清理；原版即使转移数量为零仍合并食材记录，因此通过兼容检查的满堆尝试也会清理双方。原版不兼容的堆叠仍拒绝，旧堆仅拆分则不清理。不强制新旧食品堆叠。

## 模组设置

在原生模组选项中打开「星际茶餐厅」：

* **可包装的食品包括营养膏**：默认开启，控制原版营养膏 `MealNutrientPaste`。
* **可包装的食品包括粗饲料**：默认关闭，控制食物类型带 `Kibble` 标记的食品，包括同类模组饲料。
* **包装生存食品可以再包装**：默认关闭的彩蛋选项。开启后允许以包装生存食品作为三种包装配方的原料；中文悬停提示为「……真的要开启吗w」。
* **实验性：包装食品熟食原料视为无忌口**：默认关闭，只调整包装生存食品的饮食分类，详见下节。
* **实验性：包装食品继承熟食原料心情**：默认关闭，只在实际吃包装生存食品时传递直接原料的原生食物心情，详见下节。

两项实验开关完全独立，可分别启用或同时启用。**恢复默认**按钮把上述五项恢复为：营养膏开启，其余全部关闭；原料范围随之更新，不覆盖已有订单的个人选择。

勾选立即更新配方，关闭原生设置窗口时由游戏保存。新订单取得当前默认原料；已有订单保留玩家自己的选择，新开放食品须在订单原料筛选中勾选或新建订单。关闭某类食品会立即通过配方固定筛选限制已有订单，不覆盖其个人筛选。

## 实验性：玩家决定绕到哪一步

两个实验项均默认关闭，旧设置缺少对应字段时也保持关闭。不增加物品存档数据，不扫描或改写存量食材记录；启停立即影响现有包装生存食品的分类或下一次进食，但不会删除已经获得的心情记忆。

### 包装食品的无忌口分类

原版只保存原料 `ThingDef`，不会保存那份熟食内部究竟用了什么。通用简单餐、精致餐、奢侈餐、营养膏和生存包的定义级饮食类型原本是 `Any`，再作为原料时却会被原版成品聚合判为「素食」。开启后，仅对 `MealSurvivalPack` 补上这些通用熟食的 `Any` 传递，并将 C 口粮视为「无忌口」。

不把所有餐食强行改成无忌口：明确的素食/肉食餐食变体、婴儿食物、巧克力及原版生肉/植物/动物产品分类保持原有语义；存在实际肉类原料的生存包仍为含肉。**最终范围仅限包装生存食品**，不改变「营养膏味营养膏」「奢侈餐味营养膏」「营养膏味简单食物」或酒馆等模组提供的其他餐食。实现仅对 `FoodUtility.GetFoodKind(Thing)` 加一个带设置及产物判定的 postfix，不修改食品定义。分类改变也会按原版规则改变堆叠和运输分组，不强制合堆。

### 包装食品的直接原料心情

开启后，吃一份包装生存食品时，对其记录的每种直接加工食品原料各取一次「直接吃一份」的原生食物心情。例如营养膏和奢侈餐一起包装，普通小人会同时得到营养膏的 −4 与奢侈餐的 +12。苦行者不会得到奢侈餐加成，营养膏心情也会由原版特性抵消；技术融合等文化是否免除营养膏惩罚，取决于小人实际的「不介意营养膏」准则，不硬编码文化名称。

纯 XML 定义的模组 `tasteThought` 会自动沿用其心情、持续时间和原版限制，例如萌螈族「仰望萌螈派」的「凝望深渊」−3、持续 3 天；同样复用原生直接食用心情及文化准则。**只读包装食品的直接原料，不递归查看奢侈餐等原料自己的原料，也不再次执行原料摄入。** 不复制营养、休息、娱乐、药物、食物中毒或其他 `outcomeDoers` 效果，不保证兼容第三方自定义脚本添加的心情。

按原版 `ThoughtDef` 去重，不按投入份数重复叠加；原版互斥仍生效，因此精致餐 +5 与奢侈餐 +12 不会强行共存，按记录顺序最后被原版接受的心情保留。原料记录仍受原版合堆时最多三种的限制，已被裁掉的原料不能恢复；重包装也不会找回内部丢失的原料。

这项行为仅在实际进食后的组件回调中追加记忆，不改选食 AI 或心情预览。只有 `MealSurvivalPack` 生效：营养膏味营养膏仍只承担原版的一次营养膏心情；奢侈餐味营养膏不额外获得奢侈餐加成；营养膏味简单食物不额外承担营养膏心情。两个开关让玩家自行选择保留默认的「众生平等」，只绕过饮食分类，或保留直接熟食心情；不另造心情定义或逐模组适配。

## 失能机关 C 口粮

安装 The Dead Man's Switch / The Dead Man's Switch II 且其定义 `DMS_CombatRation` 存在时，自动作为特例纳入，仅在本模组包装配方中按 **每份 2.0 营养值**计量。

不修改口粮自身的营养属性、直接食用行为或其他配方。不要求安装失能机关，不引用其程序集。实验选项只影响上述分类和食物心情；包装仍不会继承原食品的休息恢复、药物或其他特殊进食效果。

## 中英本地化

`Languages/ChineseSimplified` 与 `Languages/English` 分别存放静态单语名称、模组说明、设置、全部物品及 14 个配方的文本。基础 Def 和 About 采用英文回退。启用后模组列表与设置标题随游戏语言显示「星际茶餐厅」或「Interstellar Cha Chaan Teng」，不再合写。

原版没有 About 名称的语言注入入口，因此本地化部分仅对本模组的元数据 getter 使用 Harmony。启动语言尚未加载、模组未启用或缺少译文时回退 About 英文；getter 不加载语言、不调用翻译器，避免启动期间的语言递归。食品范围刷新及实验性饮食分类另有各自的窄范围钩子，心情传递不 patch 原版心情查询方法。

## 构建

塑料贴图的程序化生成入口、隔离预览命令与历史设计材料见 [Tools/Plastic](Tools/Plastic/README.md)。

本机 RimWorld 1.7.4995 rev309 使用 .NET 10 / Waylith，程序集针对 `net10.0` 构建：

```sh
dotnet build Source/AyameICCT/AyameICCT.csproj -c Release
```

`GameRoot` 和 `HarmonyPath` 可通过 MSBuild 属性覆盖，输出为 `Assemblies/AyameICCT.dll`。游戏安装目录仅用作引用，构建不会自动部署。不要把 Harmony DLL 复制进本模组。

最小浅测：更新后正常启动，在现有灶台的包装订单中只选 C 口粮制作一批，确认右侧食品菜单不再出现塑料，仍按原量消耗塑料，选中新成品显示「原料：C口粮」。已有订单无需重建，但新开放的食品仍须自行勾选。
